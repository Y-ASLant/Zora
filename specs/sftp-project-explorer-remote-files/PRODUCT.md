# SFTP 项目浏览器远程文件打开

## Summary

SSH 连接后的项目浏览器应显示该 SSH 会话对应的远程 SFTP 目录，并允许用户像打开本地项目文件一样双击打开远程文本文件。小型文本文件默认直接在 Zora 内部打开；大文件、二进制文件和无法判断类型的文件提供明确的预览、下载或外部打开选择。

## Problem

当前 SFTP 文件能力与项目浏览器、代码编辑器和远程文件打开体验割裂。用户连接 SSH 后仍可能在项目浏览器看到本地目录，远程文件只能作为文件传输对象处理，无法形成“浏览远程目录 -> 双击文件 -> 在 Zora 内查看/编辑 -> 保存回远程”的连续工作流。多 SSH 会话并行时，固定的 SFTP 面板和本地项目浏览器也容易让用户误判当前操作对象。

## Goals / Non-goals

### Goals

- SSH 会话打开后，项目浏览器显示该会话绑定的远程 SFTP 文件树。
- 多个 SSH 会话各自维护独立的远程根目录、当前路径、导航历史、缓存和打开文件状态。
- 双击远程文本文件默认在 Zora 内部打开，并复用现有代码编辑器体验。
- 远程文件打开、保存、刷新、冲突提示和关闭确认遵循 Zora 现有 editor/buffer 行为。
- 大文件、二进制文件、未知类型、权限错误、连接断开和远程文件变化都有明确、可恢复的用户反馈。
- 本地项目浏览器、remote-server 文件树和 SFTP 文件树共享同一个项目浏览器入口，而不是保留互相竞争的文件面板。

### Non-goals

- 本功能不实现完整远程 IDE 同步，不要求远程目录具备本地项目的 Git 状态、语言索引、全局搜索或文件 watcher 能力。
- 本功能不把 NyaTerm 的 Tauri/React 远程文件编辑窗口移植到 Zora。
- 本功能不要求手动在普通终端输入 `ssh ...` 后自动识别并接管 SFTP；第一版只保证通过 SSH 管理器打开的会话具备连接身份。
- 本功能不默认把远程文件缓存持久化到磁盘；磁盘缓存只作为外部打开和后续优化路径。

## Figma

## Behavior

1. 当用户从 SSH 管理器打开一个 SSH 会话时，当前 pane group 的项目浏览器切换到该会话的 SFTP 文件树。用户不需要手动打开独立 SFTP 面板。

2. 项目浏览器的根节点显示远程连接身份，至少包含 `user@host` 或用户配置的服务器名称。当前路径、面包屑、状态提示和错误信息都必须让用户能判断自己正在操作哪台远程机器。

3. 多个 SSH 会话并行打开时，每个会话的项目浏览器状态互相独立。切换 pane group 或 SSH 会话后，项目浏览器显示对应会话的远程路径，不复用其它 SSH 会话的路径、选中项、缓存或加载状态。

4. 本地会话或本地项目仍显示本地项目浏览器。SSH 会话结束或用户切回本地 pane group 时，项目浏览器恢复对应本地或其它会话的文件来源，不残留上一台远程机器的文件列表。

5. SFTP 文件树支持与本地项目浏览器一致的基础导航：展开目录、双击进入目录、返回、前进、上级、刷新、路径显示、加载中、空目录、权限错误和连接错误状态。

6. SFTP 文件树只显示该远程 provider 支持的操作。不可用能力不得显示成可点击按钮；例如远程 SFTP 没有本地 Git 状态时，不显示本地 Git 状态徽标作为可依赖信息。

7. 用户双击目录时，项目浏览器进入该远程目录或展开该目录，行为与当前项目浏览器的目录交互保持一致。

8. 用户双击普通文件时，Zora 先获取远程元数据并判断打开策略。判断过程异步执行，期间文件行显示短暂加载状态，不阻塞整个 UI。

9. 默认自动在 Zora 内部打开的文件必须同时满足：
   - 远程条目是普通文件。
   - 文件大小小于或等于用户设置的自动打开阈值，默认 `8 MiB`。
   - 文件根据扩展名和内容嗅探判断为文本。

10. 文本判断不能只依赖扩展名。Zora 至少读取文件开头一小段内容进行嗅探；若发现空字节或明显二进制内容，即使扩展名看起来像文本，也不得直接放进文本编辑器。

11. 小型文本文件打开后进入 Zora 内部代码编辑器 tab。tab 标题显示文件名；状态栏、悬停信息或等价位置显示远程来源，例如 `root@example:/etc/nginx/nginx.conf`。

12. 同一个 SSH 会话中的同一个远程文件重复打开时，Zora 聚焦已有 editor tab，而不是创建多个互相独立、会产生保存冲突的 tab。

13. 不同 SSH 会话中路径相同的文件被视为不同文件。`root@host-a:/etc/hosts` 和 `root@host-b:/etc/hosts` 不得复用同一个 buffer。

14. 默认编码为 UTF-8。带 UTF-8 BOM 或 UTF-16 BOM 的文件按 BOM 解码。无法无损解码的文件进入“无法作为文本安全打开”的状态，并提供下载、外部打开或仍然以替换字符预览的选择。

15. 文件超过自动打开阈值时，Zora 不自动完整加载。用户看到确认对话框，至少提供：
   - 预览前一段内容。
   - 仍然完整打开。
   - 下载到本地。
   - 外部打开。
   - 取消。

16. 二进制文件默认不进入 Zora 文本编辑器。用户看到下载或外部打开选项；如果未来支持图片、PDF 等专用预览器，可以在相同打开服务下扩展。

17. 未知类型文件先进行内容嗅探。嗅探后判断为文本则按文本文件处理；判断为二进制则按二进制处理；仍无法判断时询问用户，而不是静默下载或静默失败。

18. 文件打开失败时，项目浏览器保留当前目录和选中项，并显示可读错误。错误至少区分权限不足、文件不存在、连接断开、超时、文件过大和编码不支持。

19. 打开的远程文本文件可以编辑。编辑后 editor 显示 dirty 状态，关闭 dirty tab 前必须提示保存、丢弃或取消关闭。

20. 保存远程文件时，Zora 不得盲目覆盖远程变化。打开文件时记录远程 `size` 和 `mtime`；保存前重新读取元数据。如果远程文件在打开后发生变化，用户必须看到冲突提示。

21. 冲突提示至少提供：
   - 重新加载远程版本并丢弃本地未保存修改。
   - 覆盖保存本地版本。
   - 另存为远程新路径。
   - 取消并返回编辑器。

22. 保存成功后，editor 清除 dirty 状态，项目浏览器刷新该文件的大小和修改时间。保存失败时保留本地编辑内容，并显示可重试错误。

23. 刷新远程目录不会丢弃已打开 editor tab 中的未保存内容。若远程文件被删除或移动，已打开 tab 在保存或 reload 时显示明确的远程缺失状态。

24. Zora 对远程文本文件使用内存 LRU 缓存，以减少重复打开延迟。默认总缓存预算为 `64 MiB`，单文件自动打开阈值仍为 `8 MiB`。缓存命中必须受连接身份、远程路径、大小和修改时间约束，不能跨服务器误用。

25. 用户可以在设置中调整自动打开阈值和文本缓存总量。设置变更只影响后续打开和缓存淘汰，不强制关闭已经打开的文件。

26. 外部打开是辅助路径。外部打开远程文件时，Zora 可以下载到临时目录并打开系统或用户配置的外部编辑器；是否自动上传外部编辑器保存的修改应由单独设置控制，默认不覆盖 Zora 内部 editor 主路径。

27. 远程文件传输进度仍通过传输面板展示。直接在 Zora 内部打开小文本文件不应创建用户可见的下载任务；下载、外部打开、大文件保存和显式传输才进入传输队列。

28. 所有操作必须可取消或可恢复到稳定状态。用户取消打开、关闭对话框或网络断开时，项目浏览器和 editor 不得进入半打开、半保存或无法关闭的状态。

29. 键盘和可访问性行为跟随现有项目浏览器和 editor：Enter 打开选中项，Escape 关闭对话框，焦点从文件树进入 editor 后可通过现有快捷键返回或切换。

30. 本功能上线后，独立 SFTP 面板不再作为主要文件浏览入口。若保留旧入口用于兼容或调试，不能与项目浏览器显示两套互相矛盾的当前远程目录。
